# OCaml vs TypeScript vs Go — Сравнение систем типов

*Честно и по существу*

---

## Что такое система типов

Система типов — набор правил которые компилятор использует чтобы поймать
ошибки **до запуска** программы. Чем мощнее система типов, тем больше
ошибок компилятор находит сам, не давая программе упасть в продакшне.

Ключевой вопрос не «есть ли типы» — они есть у всех трёх языков.
Вопрос: **что именно можно выразить через систему типов** и насколько
компилятор помогает, а не мешает.

---

## TypeScript: типы как аннотации

TypeScript — это JavaScript с добавленными типами. Ключевое слово:
*добавленными*. Типы существуют только при компиляции — в рантайме их нет.

```typescript
// Описываешь тип вручную
type Alert = {
  deviceId: string;
  severity: "critical" | "warning";
};

// Но компилятор тебе доверяет — это дыра
const a = JSON.parse(data) as Alert;

// Структурная типизация: "утка"
function process(a: { deviceId: string }) { ... }
process({ deviceId: "A", extraField: 42 }); // OK — лишнее игнорируется
```

**Сильные стороны:**
- Discriminated unions: `type Shape = Circle | Rect | Triangle`
- Структурная типизация — гибко для JavaScript экосистемы
- Огромная экосистема npm, типы для большинства библиотек
- Постепенное внедрение в существующий JavaScript код

**Слабые стороны:**
- `any` отключает все проверки — легальный escape hatch используемый повсеместно
- `JSON.parse` возвращает `any` — дыра прямо в стандартной библиотеке
- `null` и `undefined` текут даже со `strict mode`
- Вывод типов слабее — часто нужны явные аннотации
- Типы стираются при компиляции — рантайм ничего не знает о типах

## Go: типы как контракты, намеренно простые

Go выбрал простоту осознанно. Система типов намеренно ограничена
ради быстрой компиляции и лёгкого онбординга. Это не недостаток — это философия.

```go
// Нет алгебраических типов
// Severity — строка без гарантий что значение допустимо
type Alert struct {
    DeviceID string
    Severity string  // может быть "critical", "warning" или "banana"
}

// Интерфейсы: структурная типизация
type Stringer interface { String() string }
// Любой тип с методом String() — неявно Stringer

// Ошибки — значения. Легко проигнорировать:
val, _ := riskyOperation()  // _ = молча игнорируем ошибку
```

**Сильные стороны:**
- Молниеносная компиляция — крупный проект за секунды
- Интерфейсы без явной декларации — гибкость без бойлерплейта
- Отличная стандартная библиотека для сетевых сервисов
- Простой онбординг — язык освоить за неделю

**Слабые стороны:**
- `nil` panic в рантайме — нет защиты на уровне типов
- Нет алгебраических типов данных
- Нет exhaustive matching — добавил вариант, компилятор не скажет
- Generics появились только в 1.18 и всё ещё ограничены
- Ошибки легко проигнорировать через `_`

## OCaml: типы как математика

OCaml пришёл из ML-семейства (Meta Language, 1973). Типы здесь — не
аннотации и не контракты. Это **логические утверждения** о программе
которые компилятор доказывает.

### 1. Вывод типов — не надо писать типы вообще

```ocaml
(* Нет ни одной аннотации типа *)
let add x y = x + y
(* Компилятор выводит: val add : int -> int -> int *)

(* Весь pipeline — без единой аннотации *)
let pipeline source =
  source
  |> with_watermarks ~latency:3000
  |> window (module Telemetry) (tumbling 30_000)
  |> aggregate Rules.compute
  |> flat_map (Rules.check Rules.fleet)
(* Если типы не совпадают → ошибка при компиляции, не в рантайме *)
```

### 2. Алгебраические типы — «одно из нескольких»

Это главное отличие. OCaml может выразить что значение — ровно одно
из нескольких вариантов, и компилятор **заставит** обработать каждый:

```ocaml
(* В Go/TypeScript нет прямого аналога *)
type event =
  | Data      of value * timestamp
  | Watermark of timestamp
  | Retract   of value * timestamp

(* Компилятор ЗАСТАВИТ обработать все три случая *)
match event with
| Data (v, t)    -> process v t
| Watermark t    -> advance_clock t
| Retract (v, t) -> undo v t
(* Забыл Retract → Warning: pattern-matching is not exhaustive *)
```

### 3. Exhaustive pattern matching

```ocaml
type severity = Critical | Warning | Info

let color = function
  | Critical -> "red"
  | Warning  -> "orange"
(* Забыл Info → Warning: this pattern-matching is not exhaustive *)

(* Добавил новый вариант → компилятор показывает ВСЕ места
   где его не обработали. В Go/TypeScript такой гарантии нет. *)
```

### 4. Нет null — вообще

```ocaml
(* В OCaml нет null и undefined.
   Вместо этого — явный тип option: *)
type 'a option = None | Some of 'a

let find_device id =
  match Hashtbl.find_opt table id with
  | None      -> (* обязан обработать — компилятор не даст забыть *)
  | Some info -> info.max_speed

(* В TypeScript: null течёт даже со strict mode
   В Go:         nil вызывает panic в рантайме
   В OCaml:      невозможно случайно разыменовать None *)
```

### 5. Параметрический полиморфизм без боксинга

```ocaml
(* Одна функция работает для любого типа
   без потери типобезопасности *)
val map : ('a -> 'b) -> 'a Stream.t -> 'b Stream.t

let speeds = map (fun t -> t.speed_kmh) telemetry_stream
(* speeds : float Stream.t — компилятор знает точный тип *)

(* В TypeScript: нужна явная аннотация или получишь any
   В Go:         до 1.18 — interface{}, с 1.18 — generics, ограниченные *)
```

### 6. Модульная система с сигнатурами

```ocaml
(* Интерфейс модуля — это тип *)
module type STATE_BACKEND = sig
  type t
  val get  : t -> string -> bytes option
  val set  : t -> string -> bytes -> unit
end

(* Функтор: принимает модуль как аргумент *)
module Make (B : STATE_BACKEND) = struct
  (* код не знает какой именно backend *)
  (* замена Memory → RocksDB = одна строка *)
end

(* Мощнее интерфейсов Go и типов TypeScript:
   модуль может содержать типы, функции, другие модули *)
```

## Честное сравнение

| Свойство | OCaml | TypeScript | Go |
|----------|-------|------------|-----|
| Вывод типов | Полный (Hindley-Milner) | Частичный | Минимальный |
| Null safety | Нет null в принципе | Опционально, утекает | nil panic в рантайме |
| Exhaustive matching | Компилятор требует | Частично | Отсутствует |
| Алгебраические типы | Да, первоклассные | Имитация через union | Отсутствуют |
| Дженерики | Да, с 1973 | Да, мощные | С 1.18, ограниченные |
| Ошибки | Result, типизированные | Исключения / any | Значения, легко игнорировать |
| Escape hatch | `Obj.magic` (явный, редкий) | `any` (повсеместный) | `interface{}` / `unsafe` |
| Простота освоения | Сложнее | Легко для JS-разработчиков | Намеренно прост |
| Экосистема | Маленькая | Огромная (npm) | Большая |
| Скорость компиляции | Быстро | Медленно (tsc) | Очень быстро |

## Где OCaml реально выигрывает

**Когда важна корректность.**
Jane Street — один из крупнейших трейдеров в мире — использует OCaml
потому что система типов делает целый класс ошибок физически невозможными.
JSCert (POPL 2014) — формальная спецификация ECMAScript 5 в Coq,
автоматически извлечённая в OCaml — ещё один пример.

**Когда меняется схема данных.**
Добавил поле в тип → компилятор показал все места где надо обновить код.
В Go и TypeScript это легко пропустить.

**Когда нужно рефакторить.**
«If it compiles, it probably works» — реальная практика у опытных
OCaml-разработчиков. В TypeScript скомпилировавшийся код может падать
из-за `any` или `null` в рантайме.

**Пример из miniFlink** — pipeline без единой аннотации типа:

```ocaml
let pipeline source =
  source
  |> Event.with_watermarks   ~latency:(seconds 3)
  |> Pipe.enrich (module Telemetry) ~from:devices ~merge:(...)
  |> Pipe.window (module Telemetry) (Pipe.tumbling (seconds 30))
  |> Pipe.aggregate Rules.compute
  |> Pipe.flat_map (Rules.check Rules.fleet)
  |> Pipe.dedup (module Alert) ~rule:(...) ~cooldown:(minutes 5)
```

Добавь поле `odometer_km` в тип `telemetry` → компилятор немедленно
укажет на все функции которые нужно обновить. Ни одна не пройдёт мимо.

## Где Go и TypeScript выигрывают

**Go:**
- Молниеносная компиляция — критично для больших команд
- Горутины и каналы — отличная модель конкурентности
- Идеален для микросервисов и сетевых сервисов
- Простой онбординг — новый разработчик продуктивен через неделю

**TypeScript:**
- Огромная экосистема npm — есть библиотека для всего
- Постепенное внедрение — можно начать с одного файла
- Лучший tooling (VSCode, ts-server)
- Фронтенд + бэкенд одним языком — один стек

## Итог

| Язык | Выбери если... |
|------|---------------|
| **OCaml** | Нужна максимальная корректность. Финансы, компиляторы, формальные системы. Компилятор — партнёр. |
| **TypeScript** | Уже есть JavaScript. Нужна экосистема npm. Команда знает JS. Фронтенд + бэкенд. |
| **Go** | Микросервисы, сетевые сервисы, быстрый онбординг. Простота и скорость компиляции важнее выразительности. |

OCaml превосходит оба по выразительности системы типов и гарантиям
корректности. Но это не делает его автоматически лучшим выбором —
всё зависит от задачи, команды и экосистемы.
