# Грамотное описание пайплайнов (literate programming)

Эта папка — **эксперимент по сравнению двух способов** подробно
документировать пайплайны miniFlink в духе «грамотного программирования»
(literate programming) Дональда Кнута. Здесь нет рабочего кода
библиотеки — только демонстрация подхода на одном примере, чтобы выбрать,
как документировать пайплайны для minePASS.

## Что такое «грамотное программирование» и зачем оно

Обычно программа пишется для компилятора, а комментарии добавляются
по краям. Дональд Кнут предложил перевернуть приоритет: писать программу
как **связный рассказ для человека**, где проза и код переплетены в
порядке изложения мысли, а не в порядке, удобном машине. Из одного такого
источника два инструмента получают разное:

- **weave** («ткать») собирает красивый документ (обычно PDF) — его читают
  люди;
- **tangle** («распутывать») извлекает чистый код — его компилирует машина.

Для системы безопасности вроде minePASS это особенно ценно: пайплайн,
который решает, поднимать ли тревогу о газе, должен **читаться как
объяснение** — почему каждый шаг именно такой, — а не только исполняться.
Ревью, аудит и просто понимание «что тут происходит» становятся проще,
когда логика сопровождается развёрнутой прозой.

## Два варианта, которые мы сравнили

Оба реализуют **один и тот же** пайплайн — газовые тревоги с порогом из
динамической таблицы уставок (порог не зашит в код, а приходит потоком).
Различие — в том, **что является первоисточником**.

### B2 — код первичен, документ генерируется из него

Файлы: [`gas_pipeline_b2.ml`](gas_pipeline_b2.ml),
[`weave.py`](weave.py), [`gas_pipeline_b2.pdf`](gas_pipeline_b2.pdf).

Источник истины — обычный `.ml`-файл. Он **компилируется как есть**, его
видят тесты, измерение покрытия и аудит. Развёрнутая проза живёт в
размеченных комментариях (`@section`, `@doc`), а небольшой скрипт
`weave.py` собирает из них и из кода документ в порядке файла.
**Шага извлечения кода нет** — то, что запускается, и есть единственный
источник.

Собрать документ:

```sh
python3 weave.py gas_pipeline_b2.ml > gas_pipeline_b2.tex
pdflatex gas_pipeline_b2.tex
```

### B3 — документ первичен, код извлекается (настоящий WEB Кнута)

Файлы: [`gas_pipeline_b3.nw`](gas_pipeline_b3.nw),
[`gas_pipeline_b3.pdf`](gas_pipeline_b3.pdf).

Источник истины — документ `.nw` (формат [noweb](https://www.cs.tufts.edu/~nr/noweb/)).
Проза и именованные куски кода (`<<...>>=`) переплетены свободно, в любом
порядке изложения. Из этого файла внешний инструмент `noweb` извлекает
готовый `.ml` (`notangle`) и собирает документ (`noweave`).

Извлечь код и собрать документ:

```sh
notangle -Rpipeline.ml gas_pipeline_b3.nw > pipeline.ml   # код для компилятора
noweave  -delay -index  gas_pipeline_b3.nw > gas_pipeline_b3.tex
pdflatex gas_pipeline_b3.tex   # нужен второй проход для перекрёстных ссылок
```

Требует установленного `noweb` (`apt-get install noweb`) и `noweb.sty`.

## Чем они отличаются на практике

| | B2 (код первичен) | B3 (документ первичен, noweb) |
|---|---|---|
| Источник истины | `.ml` | `.nw` |
| Перед компиляцией | ничего — `.ml` готов | нужен `notangle` (извлечь `.ml`) |
| Инструмент | свой `weave.py` (~150 строк) | внешний `noweb` |
| Порядок изложения | следует порядку кода | любой (чанки) |
| Авто-индекс, кросс-ссылки | нет | есть |
| Тесты/coverage/аудит | работают с источником напрямую | работают с **производным** `.ml` |

## Почему для minePASS выбран B2

Решающий довод — не эстетика, а **цепочка доверия**. В системе
безопасности недопустимо, чтобы между прозой-документом и тем, что
реально исполняется в шахте, стоял генератор кода. B2 сохраняет `.ml`
единственным источником: всё, что построено вокруг кода — property-тесты,
измерение покрытия, аудит, проверка саботажем — продолжает работать без
оговорок, потому что проверяется ровно тот файл, что запускается.

Свобода изложения у B3 красива и в этом сила идеи Кнута, но пайплайны
miniFlink и так пишутся сверху вниз (показания → обогащение → триггер), и
порядок кода почти совпадает с порядком рассказа. То есть главное
преимущество B3 здесь почти не востребовано, а его цена — лишний шаг
извлечения и производный артефакт в git — вполне реальна.

**Вывод:** для minePASS документируем пайплайны по схеме B2 — `.ml`
остаётся источником истины, рядом лежит сгенерированный из него
PDF-разбор. B3 сохранён здесь как рабочая демонстрация настоящего подхода
Кнута, на случай если он понадобится для отдельных, особо нетривиальных
пайплайнов, где свобода изложения окупит шаг извлечения.

## Файлы

| Файл | Что это |
|---|---|
| `gas_pipeline_b2.ml` | B2: грамотный модуль (источник истины, компилируется как есть) |

артефакты (`.tex`, `.aux`, извлечённый из `.nw` код) не коммитятся
(см. `.gitignore`).
