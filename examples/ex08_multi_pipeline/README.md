# Пример 8. Множество параллельных пайплайнов на реальном Kafka

Показывает, как несколько независимых пайплайнов minePASS работают
одновременно в одном процессе, читая из реальных Kafka-топиков и записывая
обратно с exactly-once — **каждый в своём домене OCaml 5**.

## Что демонстрирует

- **Декларативность.** Логика пайплайна — несколько комбинаторов
  (`pipelines.ml`): `filter` + `dedup`, `on_silence`, `window_agg` с
  медианой. Ни таймеров, ни ручного управления offset'ами.
- **Изоляция.** N пайплайнов = N независимых `run_exactly_once`. Ядро
  single-node не знает о соседях.
- **Общий вход и общий выход.** Пайплайны `voltage` и `loss` читают из
  **одного** топика `telemetry.raw` и пишут в **один** `alerts.out`.
- **Exactly-once поверх Kafka.** Транзакционный producer + ручной commit
  offset'ов через чекпоинт: при рестарте пайплайн переигрывает с
  последнего чекпоинта, не теряя и не дублируя.

## Три идентификатора, уникальные на пайплайн

Изоляция и корректность общего входа/выхода держатся ровно на трёх вещах,
которые у каждого пайплайна свои:

| Идентификатор       | Зачем уникальный                                          |
|---------------------|-----------------------------------------------------------|
| `group.id`          | Разный у читающих один топик — иначе Kafka поделит партиции между ними (consumer group), и каждый увидит лишь часть. Разные группы → каждый видит **полный** поток. |
| `transactional.id`  | Разный у пишущих в один топик — Kafka фенсит producer'ов по `transactional.id`; одинаковый → они аборт'ят транзакции друг друга. |
| checkpoint `dir`    | Разный всегда — иначе перезапишут `LATEST` друг друга.    |

Downstream-потребители `alerts.out` с `isolation.level=read_committed`
видят только закоммиченные сообщения; то, что алерты двух пайплайнов
перемешаны в топике — нормально (порядок между разными пайплайнами не
гарантируется).

## Нужен ли каждый пайплайн в своём домене? Да.

`run_exactly_once` **блокирует** вызывающий поток (внутри `Thread.join`
воркеров) и на Kafka-источнике не возвращается — источник бесконечен.
Поэтому два пайплайна нельзя запустить последовательно в одном потоке:
первый заблокирует второй.

Решение — каждый пайплайн в отдельном `Domain.spawn`. Это даёт сразу:

- пайплайны идут **одновременно** (домены не блокируют друг друга);
- **настоящий параллелизм по ядрам** между пайплайнами. В OCaml 5 разные
  домены — это разные ядра; несколько `Thread` внутри одного домена делят
  рантайм-lock и параллелизма по CPU не дают.

Итоговая иерархия параллелизма:

- **домен на пайплайн** — изоляция + параллелизм между пайплайнами;
- **Thread-воркеры внутри пайплайна** — конкурентная обработка и
  координация чекпоинтов (`run_exactly_once ~workers:4`).

Поэтому пример требует OCaml ≥ 5 (в dune: `enabled_if (>= ocaml_version 5)`).

## Две формы логики

- `pipelines.ml` — **декларативные Stream→Stream графы**. Так логику
  удобно писать, читать и тестировать. Покрыты `test_ex08_graphs.ml` на
  моках (через `Stream.of_list`, без Kafka).
- `ex08_multi_pipeline.ml` — те же алгоритмы в **per-event форме**, которую
  требует транзакционный `run_exactly_once` (он атомарно связывает
  обработку, чекпоинт и Kafka-транзакцию). Здесь же — Kafka-обвязка и
  оркестрация доменов.

Это ровно та развязка I/O от логики, ради которой graphs вынесены
отдельно: один и тот же алгоритм тестируется на списках и работает на
живом брокере.

## Файлы

- `pipelines.ml` — чистые графы (без I/O), собираются всегда;
- `test_ex08_graphs.ml` — тест графов на моках (без Kafka), собирается
  всегда, часть `dune test`;
- `ex08_multi_pipeline.ml` — Kafka-обёртка + домены, только профиль
  `rdkafka` и OCaml ≥ 5.

## Запуск

Тест логики (без брокера, любая версия OCaml):

```sh
dune exec examples/ex08_multi_pipeline/test_ex08_graphs.exe
```

Полный пример на реальном Kafka (нужен брокер на `localhost:9092`, топики
`telemetry.raw`, `gps.raw`, `alerts.out`, `positions.out`, OCaml ≥ 5,
системная librdkafka):

```sh
# rdkafka-подкаталог по умолчанию исключён из сборки; включить как в CI:
sed -i 's/ \\ rdkafka//' connectors/kafka/dune
dune exec --profile rdkafka \
  examples/ex08_multi_pipeline/ex08_multi_pipeline.exe
```
